# 麦麦合单官

**改口后重新核价，拿餐时按人核对。**

把群聊里的“加一份”“改成这个”“我随便”，整理成可核对的合单与逐人分餐看板。面向办公室午餐组织者、同学聚餐发起人，以及需要替多人核对点餐的朋友。宿主 AI 理解群聊和临时修改，麦当劳官方 MCP 提供门店、餐品、可选规格与价格，Python 负责数量、归属和预算校验，组织者明确确认后才创建订单。

已完成真实门店、菜单、套餐特调与优惠券查询、官方价格试算及本地看板生成：**三人 4 份餐品，应付 83.80 元，预算 90 元；23 项离线行为测试通过。** 未创建订单或付款。真实联调使用模拟需求与真实菜单，通过本机一次性 Streamable HTTP 探针完成，当前会话未直接加载原生麦当劳工具，详见 [接入验证记录](MCP_INTEGRATION.md#当前验证状态)。

另提供 **Python 3.10+、零第三方依赖的离线演示**，无需 Token。仓库演示文件中的人物、门店、餐品编码、优惠与报价均为合成数据。

## 一次合单，留下两份清楚的答案

- **下单前知道买什么：** 按说话者整理最新需求，区分追加与替换，把无法确认的规格列为待确认项。
- **拿到餐知道给谁：** 每份餐品都对应成员，完整套餐归同一个人，本地看板按人分组核对。
- **修改后知道哪里变了：** 当前计划保留必要的需求来源与变更说明，旧报价不能用于修改后的计划。
- **预算与确认有边界：** 以官方 `calculate-price` 返回的应付总价校验预算；报价或取餐方式变化后重新确认，不自动加购或付款。

现有离线示例与 `demo.py` 展示的三种变化：

| 场景输入 | 整理后的计划与看板结果 |
| --- | --- |
| 小王：“我也加一杯美式吧。” | 保留原汉堡，追加一杯咖啡；小王、小陈各一杯，归属清楚。 |
| 小李：“我的汉堡不要酸黄瓜。” | 保留原套餐，补充套餐内汉堡特调，看板显示“去酸黄瓜”。 |
| 小陈：“帮我改为两杯美式。” | 小陈改为两杯，小王仍是一杯；旧报价失效，提示重新试算。 |

```text
群聊原文 → 宿主 AI 整理、核对修改
                    ↓
官方 MCP：门店 / 菜单 / 套餐详情 / 门店优惠券
                    ↓
Python：数量与归属校验 → 官方价格试算 → 预算校验
                    ↓
本地分餐看板 → 组织者确认当前方案、报价与取餐方式
                    ↓
官方 MCP 创建订单 → 用户打开支付链接付款
```

自然语言处理由支持 Skills 的宿主 AI 完成。仓库不包含独立聊天服务；Skill 的本地校验与看板脚本不联网、不接收或保存 MCP Token。

## 五分钟查看离线演示

准备 Python 3.10 或更新版本，无需 `pip install`，也无需 MCP Token。

1. 下载项目，在 IDE 中将解释器设为 Python 3.10+。
2. 打开根目录 [demo.py](demo.py)，直接运行。输入、输出路径在 `if __name__ == "__main__":` 中设置，可直接修改。
3. 用浏览器打开生成的 `output/demo.html`，查看逐人餐品、数量、报价、预算和变更说明。
4. 再打开 `output/changed.html`：小陈把咖啡从一杯改成两杯，分餐数量更新，原报价立即失效，须重新试算。

也可在已激活的 Python 3.10+ 环境中从项目根目录运行：

```powershell
python demo.py
python -m unittest discover -s tests -v
```

示例输入见 [群聊文本](examples/chat.txt)、[整理后的计划](examples/plan.demo.json) 与 [合成试算响应](examples/quote.demo.json)。`demo.py` 读取已整理的计划，展示确定性校验和看板生成；它不会自行理解群聊或调用官方 MCP。

演示看板是自包含 HTML，可离线打开，支持按人筛选、勾选核对、复制清单与打印。页面上的勾选仅供人工分餐核对，不会下单或付款。当前以实际生成页面为预览，未附真实订单截图。

本地验证：Python 3.10.20 下 23 项离线行为测试通过，Skill 格式校验与内联 JavaScript 语法检查通过，离线演示已重新生成。测试覆盖分餐数量、特调保留、预算、旧报价失效、报价变化后重新确认及 HTML 注入防护。当前执行环境无可用浏览器，尚未完成浏览器视觉与交互实测；真实 MCP 联调已完成至价格试算和看板生成。

## 安装 Skill

将 [skills/mcd-group-order](skills/mcd-group-order) **整个目录**通过宿主的 Skills 导入功能安装，或复制到该宿主官方文档指定的 Skill 目录。需要同时保留 `SKILL.md`、`references/`、`scripts/` 和 `assets/`；不要只复制入口文件。不同宿主的导入方式和存放路径不同。

宿主需能够读取 Skill、运行本地 Python，并连接支持 Streamable HTTP 的 MCP Server。按 [MCP_INTEGRATION.md](MCP_INTEGRATION.md) 配置麦当劳官方 MCP 后，在宿主中使用类似请求：

## 真实使用流程

1. 组织者提供群聊、位置或目标门店，以及预算（如有）。宿主按成员整理最新需求，不把聊天中的文字当作工具调用授权。
2. 查询官方门店，由组织者选择；再查询该门店当前菜单、套餐或特调详情和当前账号可用优惠券。只用接口实际支持的编码与选项。
3. 将核对后的计划交给 `prepare_quote`，检查数量、归属和待确认项，再由宿主通过官方 MCP 调用 `calculate-price`。
4. 将本次工具返回的 `result.structuredContent` 交给 `record_quote`，绑定请求与业务结果，检查 `data.price` 应付总价是否超预算，生成本地 HTML 供核对。
5. 展示门店、逐人餐品、实际特调、总价、预算和试算返回的取餐方式。用 `confirmation_fingerprint` 绑定这一版计划、报价和取餐方式，取得组织者对当前方案的明确下单确认。
6. 用 `prepare_order` 生成参数，按实时工具 schema 检查后调用 `create-order`。将返回的支付链接交给用户付款；创建结果不明确时先查询订单，不盲目重试。

函数与数据格式只维护在 [计划与工具边界](skills/mcd-group-order/references/plan-format.md)。修改餐品、分餐归属、预算或其他计划内容后重新试算；报价或取餐方式变化后重新确认。

## 当前范围

- 单账号、单门店、立即到店取餐。暂不处理外送、预约、会员加购或多账号拼券。
- 一个完整套餐归一个人；暂不拆分套餐子项，也不计算逐人应付金额。
- Python 验证结构、数量与预算，不能替代宿主对原始需求、商品编码和真实工具结果的核对。
- 普通备注只用于展示，不代表餐厅执行特调。无法通过官方选项表达的需求必须继续确认。
- 不承诺最低价；优惠是否生效与最终应付价格以官方试算、订单及支付页面为准。
- 演示计划无法生成真实下单请求；真实使用需有效的 MCP Token 与兼容宿主。创建订单、支付及订单查询尚未实测。
